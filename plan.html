03

Settled design decisions

These are constraints for implementation, not open questions.

Common instructions stay small

Use natural, complete prose and apply unslop to human-facing writing. Host data and commit policy stay out.

Shared skills use one loading path

Expose shared skills at ~/.agents/skills/<name>, which both harnesses support.

Categories do not change IDs

A skill stored at skills/workflow/grill-me installs as grill-me.

Private network knowledge is optional

home-tailscale-network contains the private SSH mapping and can be excluded during installation.

External sources are immutable

The lock file records exact Git commits. unslop starts at 5bf2b1544db7 from cursor/plugins.

Runtime state remains local

Codex config.toml, credentials, caches, databases, UI settings, and trusted hashes remain unmanaged.

OpenCode config remains explicit

Track its current model choices, medium reasoning effort, and global allow permission.

Remote operations stay out

Preserve existing Git history and remote metadata locally. Do not rename a repository or push changes.

06

Installer contract

The same script supports linked and copied installations through one predictable interface.

Supported interface

./scripts/install.sh --link [--exclude SKILL] [--dry-run]
./scripts/install.sh --copy [--force] [--exclude SKILL] [--dry-run]
./scripts/verify.sh

Link mode

Use on machines where this repository is the editable source. Links point to owned files or locked cache entries.

Copy mode

Materialize regular files. With --force, replace previously managed targets and back up unmanaged collisions.

Exclusions

Repeatable --exclude values omit skills and remove previously managed copies from the target installation.

Local state

Record source revision, mode, target path, and hash outside the repository. Never record host identity in committed files.

Collision rule. The installer may replace a path only when its state file proves ownership or the user passed --force. Before a forced replacement, it copies the old path into the timestamped migration backup.

07

Acceptance checks

Completion requires evidence from files, parsers, and fresh harness sessions.

Repository integrity

Existing OpenCode history and remote metadata remain intact. No credential or runtime-state file is tracked.

Skill integrity

Every installed skill has valid frontmatter, a unique ID, a category, and either owned source or a locked origin.

Prompt integrity

Both global prompt paths resolve to identical content. It contains no caveman rules, commit policy, host mapping, or absolute skill path.

Harness discovery

Fresh Codex and OpenCode runs report the common instructions and the same shared skill set.

Adapter discovery

Both harnesses expose the adversarial reviewer. Only OpenCode exposes its computer-use agent. The removed Codex agents are absent.

Removal proof

A case-insensitive scan of managed sources and live targets finds no caveman or Babysitter registration.

Exclusion proof

A dry-run fixture with --exclude home-tailscale-network omits that skill without changing the rest of the installation.

Idempotence

A second install with identical options exits successfully and reports no filesystem changes.

Required evidence

  • Backup path and inventory summary.
  • Before-and-after tree limited to managed paths.
  • External skill lock revisions and successful fetch checks.
  • Static parser output for JSONC, TOML, shell, and skill frontmatter.
  • Fresh Codex and OpenCode discovery transcripts with sensitive values omitted.
  • Final no-change installer run.
08

Rollback and failure handling

The migration can stop after any phase without leaving half-owned paths.

If external fetching fails
Leave the live skill directories in place. Report the failing repository and revision. Do not substitute an unpinned branch tip.
If a harness rejects generated configuration
Restore that harness’s backed-up authored files, leave the repository sources intact for diagnosis, and do not clean up its old skill path.
If fresh-session discovery differs
Compare the harness-reported sources with the install state. Keep both old and new layouts until precedence and duplicate IDs are resolved.
If full rollback is requested
Remove only paths recorded in the installer state, restore the timestamped backup, and return the original OpenCode Git working tree to its former location. The backup is never deleted automatically.
